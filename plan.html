Implementation report

OCR Review is now built to recover, continue, and explain failures.

This hardening pass added typed errors, local diagnostics, snapshot recovery, explicit export outcomes, sidecar startup diagnosis, and partial multi-page OCR preservation.

Implemented Verified: macOS build succeeded Verified: 36 Python tests passed Local diagnostics only

What changed

The app now treats failures as first-class events instead of silent side effects. Successful OCR pages are saved as they complete, exports report success/cancel/failure, sidecar failures include actionable causes, and document saves keep versioned snapshots.

Reliability

Typed errors and operation state

AppError, OperationState, and DiagnosticsLogger provide one path for user messages and technical logs.

Persistence

Recoverable snapshots

Each job has current.json plus timestamped snapshots. The app restores the newest valid backup if current is corrupt.

OCR

Partial success is preserved

All-page OCR now saves page-by-page, tracks failed pages, supports retry, and keeps completed pages after cancellation.

Denoise

Only signal, less noise

Repeated headers, footers, and page numbers can be removed from OCR text as reversible edits.

Multi-page OCR behavior

  • Successful pages are merged into the document and saved immediately.
  • Failed pages are marked in the thumbnail strip.
  • The current failed page shows a Retry Page action.
  • Duplicate OCR for the same page is blocked.
  • Late OCR results are ignored if the user has moved to another document.
  • Cancellation keeps all completed pages.

Export behavior

  • Exports return .saved, .cancelled, or .failed.
  • Destination writability is validated before writing.
  • Write failures show inline notices with recovery guidance.
  • Searchable PDF export uploads from a temp multipart file instead of a full in-memory body.
  • Exports remain explicit: only OCR'd pages are included until all pages are recognized.

Signal denoiser

A new Denoise action detects repeated edge text and page-number patterns, confirms the cleanup, then applies it as editable text while preserving original OCR for Revert.

Noise type How it is handled
Running headers Repeated top-band lines across OCR'd pages are removed after confirmation.
Running footers Repeated bottom-band lines across OCR'd pages are removed after confirmation.
Page numbers Patterns like 1, - 1 -, Page 1, Page 1 of 50, and 1/50 are removed from page edges.

Sidecar diagnostics

The sidecar manager now captures stdout and stderr into local diagnostics and maps common startup failures to user-safe, actionable messages.

Failure User-facing result
Missing project path Set the MarkItDown repository path in Settings.
Missing uv Install uv or add it to PATH, then restart the sidecar.
Port in use Stop the other process or change the sidecar URL, then retry.
Bad API import/project root Set the repository root in Settings.
Health timeout Verify URL and project path, then retry.

Local logs

Diagnostics are local only and rotate automatically.

Operating principle

OCR Review should never silently discard user work. When something fails, the app should keep successful pages, keep editor state, save recoverable snapshots, tell the user what happened, provide a recovery action, and log technical context locally.
